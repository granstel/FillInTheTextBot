# Нагрузочные тесты (k6)

Нагрузочный стенд гоняет happy path story-бота через Yandex-эндпоинт против
поднятых рядом приложения, эмулятора Dialogflow и Redis. Всё собирается из
исходников — нагрузка идёт по текущему коду.

## Что именно тестируется

Один проход k6 = одна пользовательская сессия из реплик, каждая из которых
попадает в реальный интент и прогоняет весь конвейер:

```
HTTP → контроллер → ConversationService → gRPC в Dialogflow-эмулятор → Redis → ответ
```

Последовательность реплик: Welcome → «что ты умеешь» → «покажи список историй»
→ «помоги мне» → «выйти», затем по кругу с новой сессией.

### Важно про эмулятор

Dialogflow-эмулятор — **стаб**: интент ищется по имени события или **точной
обучающей фразе**, без разбора языка, **без слот-филлинга и контекстов**.
Поэтому «сочинить историю от начала до конца» (заполнить слоты словами и
получить итоговый текст) на нём **невозможно** — многошаговый диалог со слотами
не воспроизводится. Проверено на живом стенде: шаги выбора истории («новый»,
«начать», конкретная история) вырождаются в «нет текстов»/Fallback. Поэтому
скрипт гоняет достижимую часть happy path — реплики, дающие осмысленный ответ.

## Профиль нагрузки

- Пик — **18 rps** (запросов в секунду).
- Плавный подъём 0→18 (1 мин), пик 18 (1 мин), плавный спуск 18→0 (1 мин).

Настраивается переменными окружения `PEAK_RPS`, `RAMP_DURATION`, `PEAK_DURATION`.

## Запуск одной командой

Из корня репозитория:

```bash
docker compose -f loadtest/docker-compose.loadtest.yml up --build --abort-on-container-exit --exit-code-from k6
```

Команда собирает образы, поднимает стенд, запускает k6 и завершается **кодом
выхода k6**: если пороги (thresholds) не пройдены — команда падает. По окончании
остановите и уберите стенд:

```bash
docker compose -f loadtest/docker-compose.loadtest.yml down -v
```

Короткий прогон для проверки (сокращённые фазы):

```bash
RAMP_DURATION=4s PEAK_DURATION=8s docker compose -f loadtest/docker-compose.loadtest.yml up --build --abort-on-container-exit --exit-code-from k6
```

## Пороги (thresholds)

- `http_req_failed < 1%` — почти нет сетевых ошибок / не-2xx;
- `http_req_duration p95 < 800 мс`;
- `checks > 99%` — почти все смысловые проверки (200, есть текст, не Fallback) прошли.

При нарушении любого порога k6 возвращает ненулевой код, и команда/CI падают.

## CI

Отдельный workflow `.github/workflows/loadtest.yml` запускается **вручную**
(`workflow_dispatch`); параметры профиля можно задать при запуске.

## Файлы

- `docker-compose.loadtest.yml` — стенд: приложение + эмулятор + Redis + k6.
- `k6/story-happy-path.js` — сам нагрузочный сценарий.
- `k6/probe.js` — вспомогательный скрипт: прогоняет набор реплик и печатает
  ответы (удобно проверить, какие фразы во что попадают). Запуск:
  `docker compose -f loadtest/docker-compose.loadtest.yml run --rm k6 run /scripts/probe.js`.
- `config/appsettings.Yandex.json` — пустой `IncomingToken`, чтобы `/yandex`
  был доступен без токена (монтируется в контейнер приложения).
