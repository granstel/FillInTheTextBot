# Нагрузочные тесты (k6)

Нагрузочный стенд гоняет основной путь пользователя — **сочинение истории** — через
Yandex-эндпоинт против поднятых рядом приложения, эмулятора Dialogflow и Redis.
Всё собирается из исходников — нагрузка идёт по текущему коду.

## Что именно тестируется

Один проход k6 = одна пользовательская сессия: выбор истории, затем бот по очереди
спрашивает слова, и на последнее слово приходит **собранная история с подставленными
словами**. Каждый запрос прогоняет весь конвейер:

```
HTTP → контроллер → ConversationService → gRPC в Dialogflow-эмулятор → Redis → ответ
```

Последовательность (история «29-late», 6 слов):

```
Welcome → «опоздала в больницу» → 3 → медведь → два → зайцы → лес → 5 → готовая история
```

затем по кругу с новой сессией. Отдельная проверка `история собрана` подтверждает,
что на финальном шаге приходит именно собранный текст («Вот что получилось: …»).

### Про эмулятор

Dialogflow-эмулятор — облегчённый локальный стаб (без разбора естественного языка:
интент ищется по событию или **точной обучающей фразе**), но он **поддерживает
слот-филлинг**: для интентов с обязательными параметрами спрашивает их по очереди
и подставляет ответы в шаблон. Поэтому путь сочинения проходит от начала до конца
с выводом результата. Значения слов произвольны — эмулятор их не валидирует.

## Профиль нагрузки

- Пик — **18 rps** (запросов в секунду).
- Плавный подъём 0→18 (1 мин), пик 18 (1 мин), плавный спуск 18→0 (1 мин).

Настраивается переменными окружения `PEAK_RPS`, `RAMP_DURATION`, `PEAK_DURATION`.

## Запуск одной командой

Из корня репозитория:

```bash
docker compose -f loadtest/docker-compose.loadtest.yml up --build --abort-on-container-exit --exit-code-from k6
```

Команда собирает образы, поднимает стенд, запускает k6 и завершается **кодом
выхода k6**: если пороги (thresholds) не пройдены — команда падает. По окончании
остановите и уберите стенд:

```bash
docker compose -f loadtest/docker-compose.loadtest.yml down -v
```

Короткий прогон для проверки (сокращённые фазы):

```bash
RAMP_DURATION=4s PEAK_DURATION=8s docker compose -f loadtest/docker-compose.loadtest.yml up --build --abort-on-container-exit --exit-code-from k6
```

## Пороги (thresholds)

- `http_req_failed < 1%` — почти нет сетевых ошибок / не-2xx;
- `http_req_duration p95 < 800 мс`;
- `checks > 99%` — почти все смысловые проверки (200, есть текст, не Fallback,
  история собрана) прошли.

При нарушении любого порога k6 возвращает ненулевой код, и команда/CI падают.

## CI

Отдельный workflow `.github/workflows/loadtest.yml` запускается **вручную**
(`workflow_dispatch`); параметры профиля можно задать при запуске.

## Файлы

- `docker-compose.loadtest.yml` — стенд: приложение + эмулятор + Redis + k6.
- `k6/story-happy-path.js` — нагрузочный сценарий сочинения истории.
- `k6/probe.js` — вспомогательный скрипт: прогоняет один полный путь истории и
  печатает ответы (удобно посмотреть, что во что попадает). Запуск:
  `docker compose -f loadtest/docker-compose.loadtest.yml run --rm k6 run /scripts/probe.js`.
- `config/appsettings.Yandex.json` — пустой `IncomingToken`, чтобы `/yandex`
  был доступен без токена (монтируется в контейнер приложения).
